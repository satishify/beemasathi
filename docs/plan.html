Fix the corpus, then build the agents

Week 1 is deliberately unglamorous. Until documents have unique identities, the catalogue matches the vector store, and a frozen question set exists, every later number measures the wrong thing.

Weekly plan and gates

WeekWorkstreamGate
1 Corpus integrity and evaluation freeze: content-addressed document IDs and reindex, demo data purged, document-type mapping fixed, catalogue reconciled, IRDAI scan root added, frozen 100-question set with gold notes, baselines measured. G1 — zero chunks without provenance, zero collisions, catalogue equals vector store, 100 questions versioned.
2 Hybrid retrieval and evidence quality: BM25 plus dense, authority-aware reranking, calibrated threshold, clause- and table-aware chunking with OCR fallback, UIN and effective date in metadata, citation contract. G2 — Recall@5 ≥ 0.80 and wording share ≥ 0.85 (interim; final 0.85 and 0.90).
3 Agentic layer: router, retrieval, authority resolver, clause analyst, claim-risk and critic agents; typed tool schemas; persistent state, retries and budgets; trace store; agentic versus RAG-only comparison. G3 — task completion ≥ 95%, tool success ≥ 98%, critic catches injected instructions.
4 Evaluation, hardening and delivery: full evaluation and ablations, failure taxonomy, red-team report, observability dashboard, API and UI integration, deployment pack, report and demo. G4 — Section 5 targets met or documented with a remediation plan.

Risks

RiskMitigation
Insurer sites block automated access or change URLsOfficial-domain crawler plus documented manual acquisition and provenance review; no third-party mirrors
Policy revisions silently supersede indexed documentsRevision date and UIN in metadata, freshness monitor, scheduled re-crawl with diff alerts
Scanned or table-heavy PDFs extract poorlyOCR fallback with an ocr_derived flag, table-aware extraction, per-document quality metric
Brochure text contaminates coverage answersAuthority-aware reranking, wording-first policy, brochure share measured in evaluation
Hallucinated coverage or UINRefusal-first prompt, critic entailment check, citation-required answers, UIN verified against metadata
LLM judge is generous or biasedDifferent judge model, rules override the judge, 20% human audit, disagreement reported
Prompt injection through uploaded PDFsDelimited untrusted content, injection scan, critic check, nine implemented attack probes with a fifteen-case target
Scope creep into legal or claim adjudicationExplicit non-goals, informational-only framing, human verification, no claim filing

Deliverables

  • Working application with a FastAPI service and a Streamlit demonstration client.
  • Reproducible repository with pinned dependencies, tests and a one-command local start.
  • Documented knowledge base with a manifest, SHA-256 hashes, UIN mapping, revision dates and review sign-off.
  • Agent execution and tracing dashboard showing plans, tool calls, evidence, verdicts, tokens and latency.
  • Evaluation report: 100 frozen questions, five systems, four ablations, a failure taxonomy.
  • Responsible-AI and prompt-injection testing report.
  • Twelve-page technical report and a ten-minute demonstration.

Demo success criteria

  1. A coverage question returns a clause-level citation with insurer, product, UIN, document type, page, section and source URL.
  2. An insurer with no loaded wording returns a clean refusal that names the gap.
  3. A brochure-only product is answered with an explicit summary warning; where a wording exists, wording evidence is used.
  4. A two-insurer comparison returns evidence from both insurers.
  5. A claim scenario returns per-rule findings linked to clauses, or explicitly labelled defaults, and never gives unsafe advice.
  6. A poisoned uploaded PDF cannot change system behaviour.
  7. The trace dashboard reproduces every step of a demo answer.
  8. The evaluation report shows the frozen 100-question results, baselines, ablations and failure distribution.
